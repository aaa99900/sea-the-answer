# 0017. 문서 분석 토큰만 제한된 메모리에서 재사용

- 상태: 제안 (로컬 구현·검증, 팀 검토 전)
- 날짜: 2026-10-28
- 결정자: 손태호 제안
- 관련: [계획](../plans/2026-10-28-search-token-reuse.md), [기존 구조](../architecture.md)

## 배경

프로파일에서 동일 corpus의 형태소 분석이 대부분의 검색 시간을 차지했다. 기존의 요청별 권한·corpus·BM25 인덱스 생성은 유지하면서 순수 분석 결과를 재사용한다.

## 결정

현재 후보의 title/reference/heading/text를 기존 방식대로 합친 문자열의 SHA-256을 키로 사용한다. 값은 불변 토큰 튜플이며, 프로세스별 최대 2,048항목·계산된 객체 크기 합 16MiB의 LRU에 저장한다. 너무 큰 단일 항목은 저장하지 않는다. 원문·계정·질의·검색 결과·점수·BM25 인덱스는 캐시하지 않는다.

권한·활성 개정·종류·선택 문서 필터는 기존 저장 계층에서 매 요청 수행하고, BM25 통계는 그 후보만으로 재생성한다. 제목·출처·절·본문 변경은 새 키가 되며, 캐시된 토큰으로 원래 문서 행을 복원하거나 반환하지 않는다. 동점 순서·점수·인용·메타데이터는 현재 후보를 따른다. 어휘 사전·분석 코드 배포 시 프로세스를 재시작한다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 분석을 매번 수행 | 단순, 보관 없음 | 955청크 반복 검색에서 수 초 소요 |
| 권한별 전체 인덱스 캐시 | 더 빠른 가능성 | 변경·권한·복구 시 무효화와 메모리 관리가 복잡 |
| DB에 토큰 저장 | 재시작 후 재사용 | 스키마·재색인·배포 변경 필요 |
| 내용별 토큰만 재사용 | 점수와 권한 인덱스는 현재 후보로 유지 | 최초·퇴출된 청크는 다시 분석, 토큰 메모리 관리 필요 |

## 결과

분석 결과도 민감한 문서 단어를 포함하므로 보안상 무해하다고 간주하지 않는다. 디스크·로그·API에 토큰을 추가 노출하지 않고 메모리의 크기와 항목 수를 제한한다. 삭제·권한 변경 때 기존 토큰은 LRU 퇴출이나 재시작까지 메모리에 남을 수 있으나, 현재 DB 후보에서 제외된 문서가 검색 결과나 점수에 참여하지 않는다. 캐시 존재에 따른 실행 시간 차이는 발생할 수 있다.

16MiB는 키·튜플·문자열의 `sys.getsizeof` 합 기준이며 딕셔너리 관리 비용과 프로세스 전체 RSS의 상한은 아니다. 최대 항목 수로 관리 오버헤드도 제한한다. 같은 내용의 동시 miss는 중복 분석될 수 있으나 결과·메모리 제한은 락으로 보호한다. 반환 목록은 복사하여 호출자의 변경이 캐시에 전파되지 않는다.

기존 채택 ADR의 본문은 수정하지 않는다. 이 제안이 팀에 채택되기 전에는 로컬 검증 결과로만 보고한다.
