# 0016 — 개인 계정과 서버의 업무 접근 통제

- 상태: 채택
- 날짜: 2026-10-21
- 결정: 사용자 요청에 따른 인증 우선 구현
- 관련: [인증 계약](../specs/authentication.md), [작업 계획](../plans/2026-10-21-crew-admin-auth.md)

## 배경

기존 ADR 0004의 게스트 사용과 공용 기본 관리자 자격증명으로는 사용자를 식별하고 업무 권한을 회수하기 어렵다. 사용자에게 실제 규정을 조사한 후 발급·접근 정책을 정하도록 위임받았다.

## 근거와 적용 범위

- [개인정보의 안전성 확보조치 기준](https://www.law.go.kr/admRulLsInfoP.do?admRulId=73493&efYd=0): 개인정보를 처리하는 경우 접근 권한 관리, 접근통제, 비밀번호 보호, 접속기록 관리가 필요하다. 제5조의 최소 권한·개별 계정·인증 실패 제한을 설계에 반영한다.
- [개인정보보호위원회의 2025-10-31 개정 설명](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=11531): 일부 접근 권한·접근통제·접속기록 개정은 1년 유예된다. 2026-10-21 현재 아직 시행 전인 부분을 이미 시행 중이라고 표시하지 않는다. 국가법령정보센터의 현행 표제는 2026-7-1 개정이며, 개별 조문과 부칙의 시행일을 함께 확인해야 한다.
- [IMO MSC-FAL.1/Circ.3/Rev.4](https://wwwcdn.imo.org/localresources/en/OurWork/Facilitation/FAL%20related%20nonmandatory%20documents/MSC-FAL.1-Circ.3-Rev.4.pdf), 3.5.3: 개인별 자격증명, 일반·특권 계정 구분, 퇴직자 접근 회수, 기본 비밀번호 교체 등을 권고한다. 선박 사이버 위험관리 지침이며, 이 앱에 대한 인증서나 특정 로그인 화면의 의무 규정은 아니다.

## 결정

관리자가 실제 업무 배정을 확인하고 개인 계정을 발급한다. 모든 업무 API는 인증을 요구하며, 선원은 `operator`, 관리자는 `admin`, 열람만 필요한 계정은 기존 `viewer` 역할을 사용한다. 역할은 서버 저장값으로 결정한다. 신규 공개 회원가입이나 브라우저가 고르는 관리자 역할은 제공하지 않는다.

기존 FastAPI 세션을 확장하여 오프라인 실행을 유지한다. 계정 발급·비밀번호 재설정 후 본인 비밀번호로 교체하기 전에는 업무 접근을 막는다. 신규 설치에 공통 비밀번호를 내장하지 않는다. 권한·활성 상태·비밀번호 변경은 기존 세션을 무효화한다. 서버의 권한 검사와 검색 단계의 문서 범위 필터를 함께 유지한다.

로그인 필수와 관리자 발급은 최소 권한 원칙을 구현하기 위한 **프로젝트 정책**이다. 공개 법령 문서 자체가 법적으로 모두 비공개라는 의미는 아니다. 앱은 공개 자료와 내부 운항·사용자 자료를 함께 다루므로 현재 업무 화면 전체에 일관된 경계를 둔다.

## 대안

| 대안 | 판단 |
|---|---|
| 공개 회원가입 후 자동 선원 권한 | 실제 업무 배정을 확인할 수 없어 제외 |
| 외부 인증 SaaS로 교체 | 선내 오프라인 운용과 기존 FastAPI 경계에 맞지 않아 현재 도입하지 않음 |
| 게스트 열람 유지 | 공개/내부 데이터의 화면 경계가 분리되지 않아 이번 범위에서는 제외 |

## 결과

ADR 0004를 대체한다. 계정·접속 정책을 구현해도 전체 법규 준수가 자동으로 완료되지는 않는다. 운영자는 개인정보 처리 근거·고지·보존 기간, 로그의 별도 보관·점검, HTTPS와 외부 접근의 VPN/MFA, 기국·선사의 안전관리체계 적용을 확정해야 한다. 선사·선박이 특정되지 않았으므로 IACS나 기국별 의무를 일괄 적용했다고 주장하지 않는다.

번호 0015는 대기 중인 팀 PR #16에서 사용하므로 충돌을 피하려고 0016을 배정한다.
