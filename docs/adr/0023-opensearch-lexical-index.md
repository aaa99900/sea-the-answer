# 0023. 키워드 검색은 OpenSearch와 Nori로 수행한다

- 상태: 채택
- 날짜: 2026-11-11
- 결정자: 문서/RAG 담당자 요청
- 관련: [명세](../specs/rag-lexical.md), [계획](../plans/2026-11-11-opensearch-retrieval.md)

## 배경

요청마다 전체 후보를 분석하고 Python BM25 객체를 생성한다. 사용자 결정에 따라 Kiwi를 제거하고 전체 색인 통계를 허용한다.

## 결정

OpenSearch 3.9.0 + 같은 배포의 analysis-nori를 전용 이미지로 추가한다. PostgreSQL은 원본이고 검색 색인은 재생성 가능하다. 독립 PostgreSQL outbox와 worker를 사용하며 기존 벡터 작업 완료 상태를 공유하지 않는다. 문서·메타데이터·청크 변경 트리거는 같은 트랜잭션에서 요청을 보존한다. 검색은 PG 허용 후보의 현재 내용 해시로 제한하고 반환 후 PG를 다시 확인한다.

OpenSearch BM25와 Chroma가 준비되면 기존 RRF를 사용한다. 한 엔진만 사용 가능하면 그 엔진으로 검색하고 진단을 남긴다. 둘 다 불가하면 명시적 503을 반환한다. Kiwi/rank-bm25 fallback은 없다. ADR 0022의 벡터 준비 정책은 유지하되 BM25를 로컬에서 항상 실행할 수 있다는 전제는 이 결정으로 대체한다.

## 대안과 결과

직접 역인덱스 구현은 저장·동기화·랭킹 유지 비용이 크고, PostgreSQL 확장은 DB 이미지 변경이 필요하다. 별도 엔진은 메모리와 운영 비용·비동기 지연을 추가하지만 반복 분석/인덱스 생성을 검색에서 제거한다. 전역 통계와 Nori의 순위 변화는 별도 평가 대상이다. 개발 Compose의 인증 없는 엔진은 전용 내부 네트워크에만 두며 공개 포트를 제공하지 않는다. 외부 운영 연결은 TLS·인증을 구성한다.
