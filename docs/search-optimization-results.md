# 문서 토큰 재사용 개선과 측정 결과 — 2026-10-28

## 무엇을 개선했나

기존 검색은 매 요청 같은 문서를 다시 형태소 분석했다. 955청크의 한 요청 프로파일에서 전체 4.525초 중 청크 분석 4.475초, Kiwi tokenize 호출 16,043회를 확인했다. 검색 순위 계산식·질의 분류·동의어·청킹을 바꾸지 않고, 동일 내용 청크의 분석 토큰만 크기 제한 메모리에서 재사용하도록 변경했다.

- API·DB·LLM 전체 응답 시간이 아니다. 최초 실행에는 지연이 남고, 문서 변경·재시작·캐시 용량 초과 시 다시 분석한다. 큰 corpus는 토큰 재사용 이후에도 매 요청 BM25 인덱싱 비용이 있다.

## 권한과 변경 처리

1. 기존 `DocumentStore.search_candidates()`가 현재 DB에서 권한·선택 문서·활성 개정을 확인한다.
2. 그 후보의 title/reference/heading/text 전체를 해시한다. 같은 내용이면 토큰만 재사용하고 바뀌면 다시 분석한다.
3. BM25 통계·인덱스는 현재 허용 후보만으로 새로 만든다. 권한별 전체 인덱스나 검색 결과를 재사용하지 않는다.
4. 결과는 현재 후보 행에서 생성한다. 페이지·URL·메타데이터 변경도 현재 값을 반환한다.

캐시는 최대 2,048항목·계산한 객체 크기 합 16MiB의 LRU다. 원문·사용자 질문·검색 결과·계정은 보관하지 않지만 토큰에도 민감한 단어가 포함될 수 있다. 삭제/권한 변경 후 토큰이 잠시 메모리에 남는 한계와 전체 RSS가 16MiB로 제한되는 것이 아니라는 점은 [ADR 0017](adr/0017-bounded-chunk-token-reuse.md)에 기록했다. 어휘·분석 코드 배포 시 재시작한다.

README 날짜의 불필요한 변경은 제거했다. #14 자체는 조회 당시 GitHub가 현재 main과 `CONFLICTING`으로 표시했으며, 이번 브랜치와의 검색 코드 충돌을 의미하지 않는다. #14나 팀 저장소는 수정하지 않았다.

추가로 두 문서를 먼저 검색해 캐시를 채운 다음 하나만 선택했을 때 선택하지 않은 문서의 토큰이 결과·점수에 섞이지 않는 회귀 테스트를 보강했다. 캐시 테스트 명칭도 실제 검증 범위에 맞췄다. 관련 테스트 **120 통과(7.63초)**, 문서 링크·diff 공백 검사를 확인했다. 이번 재점검은 런타임 코드를 바꾸지 않았으므로 기존 속도 측정·전체 backend 496개·Docker 7개 결과는 그대로 보존하며, 새 전체 테스트 결과로 부풀려 집계하지 않는다.

PR 제출 준비에서 Git의 LF 원문과 Windows CRLF 작업 파일의 바이트 해시가 다름을 발견했다. 평가셋의 원문 고정은 정규화한 JSON 내용 해시로 보완하고 결과의 파일 바이트 해시는 재현 정보로 유지했다. CRLF/LF·들여쓰기 동일 내용 허용 및 실제 본문 변경 거부 테스트를 추가하여 관련 **122 통과(5.27초)**. 질문·근거·검색 런타임 코드는 변경하지 않았으며 기존 결과는 당시 측정 기록으로 보존한다.
